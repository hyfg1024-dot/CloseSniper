# 尾盘狙击 · CloseSniper

面向 A 股“14:30 尾盘观察、次日早盘退出”思路的免费筛选工具。英文项目名为 **CloseSniper**。它先用涨幅、量比、换手率和流通市值做硬过滤，再检查成交量、均线、分时均价线、尾盘回踩与热点概念。

> 本项目只用于学习和策略研究，不连接券商、不自动下单，也不构成投资建议。免费行情可能延迟或中断，请在交易前以券商行情为准。

## macOS 一键启动

1. 在 GitHub 页面选择 **Code → Download ZIP**，解压。
2. 双击 `启动尾盘雷达.command`。
3. 首次启动会创建 `.venv` 并安装依赖，通常需要几分钟；以后会直接启动。
4. 浏览器打开后，在交易日 14:30–15:00 选择严格标准或改进流程扫描。

今日筛选提供两个入口：

- **严格标准扫描**：按初始标准要求现价 ≥ MA5 > MA10 > MA20 > MA60，且四条均线均较 5 日前上升；三次均入选后独立进入严格次日校验。
- **改进流程扫描**：在实时日K确认基础上要求现价 ≥ MA5 > MA10 > MA20 > MA60，并过滤近10日涨幅超过12%、高于MA20超过10%、近10日出现单日涨幅超过8%的高位标的。
- 页面倒计时会提醒 14:30 首次观察、14:45 复核和 14:52 最终扫描。
- 双击 `安装每日校验.command` 后，14:30、14:45 自动扫描并缓存当天日线，两次各限时150秒；14:52独立计算严格最终名单，按 `20% × 14:30评分 + 30% × 14:45评分 + 50% × 14:52评分` 排序。
- 自动采样检查供应商完整快照中所有硬条件通过的股票，不再截取前30/80只；任何候选行情缺失或超时都标记失败，不以部分结果冒充全量结果。手动预览仍保留数量上限。
- 14:52只复核前两次严格入选交集：更新腾讯报价与全天分钟线，重新计算原有全部严格条件。历史日线复用当天缓存，题材加分沿用14:45信息；不把14:45的通过结论直接当成14:52的通过结论。
- 14:52:40为计算硬截止；超时子进程会被终止。完整结果或明确失败状态随即保存并推送，网页每5秒刷新。行情缺失、前序迟到或参数不一致时不会以零候选冒充成功。Telegram使用单次短超时；网络送达不属于本机可保证的时间。
- 原架构全市场复核保留为14:54独立任务，仅在网页存档对照，不覆盖正式严格结果、不写入正式次日校验、不再推送第二份推荐。
- 新旧数据源及扫描范围不同，不能保证与旧版全市场前30只重扫逐项相同；严格条件和评分公式保持不变。另修正了部分腾讯日线/科创板报价成交量的手/股单位错误，修正后边界股票的结果可能变化。
- “今日筛选”保留严格标准与改进流程入口；后台14:30、14:45更新两种口径，14:52专用于严格终判，改进流程仅供风险辅助。
- 页面保留严格14:30、14:45及14:52交集复核结果，最后单独展示严格加权名单；零候选节点也会明确标记为已执行。改进流程只保留前两次风险观察及14:54对照，不再等待或推荐改进最终名单。
- 自动任务部署在 `~/Library/Application Support/CloseSniper`，不依赖网页保持打开。各节点使用独立锁，前一轮慢请求不会使14:52排队到收盘后；准时结果冻结后手动重扫也不会覆盖它。
- 前两次采样只在150秒总预算内重试；14:52只读交集实时数据，不走全市场接口。分钟行情采用有界请求与并发，无响应的后台线程由外部进程硬截止兜底。
- 页面会明确区分“扫描成功但0只候选”和“行情读取失败”；14:52仍缺少节点时，Telegram会推送失败说明而不是静默无消息。
- 左侧“Telegram最终结果推送”可在本机输入独立Bot Token、自动识别已发送 `/start` 的Chat ID并发送测试消息；启用后推送严格连续两次观察、严格准时终判和次日10:00观察。改进流程名单不再推送。Token保存在本机权限为`600`的配置文件中，不进入GitHub。
- 自动任务依赖Mac在对应时点保持开机且未休眠；免费行情无法确认当日指数分钟数据时会放弃存档，避免节假日或陈旧行情形成假信号。

### 次日校验

- 三个工作台页面顶部统一显示“扫描运行记录”，每5秒刷新并展示当天严格终判；“最近扫描日”“最近三次稳定信号日”“最近严格校验日”分别统计。
- 每日运行表保留零候选日；`0` 表示已保存扫描但无入选，空白表示缺少该节点的严格结果。第三节点在14:53或以后完成即标记迟到；前两次超过3分钟标记迟到。
- 收益表只增加真实的严格三次稳定信号；若最近信号日早于扫描日，通常表示后续未产生新信号，应结合运行表确认，而不能仅凭收益表最后日期判断程序停止。
- 个股行情缺失会保存异常说明；候选日线或分时全部失败时按失败重试，不记成正常零候选。
- 本机从 [12Agent](http://127.0.0.1:18888/) 的 CloseSniper 入口启动，专用地址为 `http://127.0.0.1:18502/`。

- 交易日14:30、14:45分别保存观察快照，14:52任务保存最终筛选；记录保存在本机 `~/Library/Application Support/CloseSniper/data/closesniper.db`，不会上传 GitHub。
- “次日校验”分别显示次一交易日 9:30、9:45、10:30 收益，以及 15 分钟和 60 分钟区间的最高收益与最大回撤。
- 次日 9:30–9:50 可点击早盘按钮：9:45前保存开盘与点击时快照，9:45后完成固定口径校验；只有固定9:45数据进入历史统计。
- 同一自动任务还会在每个工作日9:45、10:01和10:30分阶段运行校验与观察；错过校验时可在“次日校验”页面补算。
- 使用已核验的2026年沪深离线交易日历（含长假），只允许真正下一交易日的数据；缺失时保留待补齐，不拿更晚一天代替。未知年份停止推断，需在新年开始前更新官方交易日历。
- 要求连续且有效的分钟线与精确时点，不再用9:59/10:29代替10:00/10:30；允许供应商首根一分钟线以9:30或9:31标记，开盘价仍是该根的开价代理，不是逐笔成交记录。
- 严格10:01可先完成10:00校验，10:30再补齐。首次10:00观察不被后续运行覆盖；行情证据追加保存，修订前结果留档。异常日期和缺少依据的修复记录单独隔离，不进入胜率统计，原数据不删除。
- 分钟读取采用有界子进程，免费接口卡住不会无限阻塞后续校验。历史补算不保证能恢复供应商已过期的分钟数据。
- “历史表现”对比 9:30、9:45、10:30 胜率、60分钟冲高概率和逐日表现；零候选日也会留档。

如果 macOS 提示无法打开，可在终端进入项目目录执行：

```bash
chmod +x 启动尾盘雷达.command
./启动尾盘雷达.command
```

要求：macOS 12 或更高版本、Python 3.11 或更高版本、可访问互联网。

## 运行逻辑

硬条件默认值：

- 当日涨幅 3%–5%
- 量比 ≥ 1
- 换手率 5%–10%
- 流通市值 50亿–200亿元
- 排除 ST / *ST、退市整理、上市首日 N/C、北交所股票

技术确认：

- 近 5 日量能总体阶梯放大
- 收盘价 ≥ MA5 > MA10 > MA20 > MA60，均线同步上行
- 至少 70% 分钟价格在成交均价线上方
- 个股日内涨幅高于同期上证指数
- 最新价不破均价线，距最近 30 分钟高点不超过 1.2%
- 实时涨幅前六的概念板块作为加分项

结果会先列出“候选”，再列出“观察”；同组按 100 分策略匹配度从高到低排序，并展示每只股票的主要优势。

全部参数可在左侧调整手动扫描。手动预览最多深筛前30只（量比缺失时扩至80）；后台自动采样使用固定默认严格参数，深筛全部硬条件合格股，若150秒内无法完整确认则明确失败。14:52交集复核不设数量截断。

## 开发运行

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

离线检查界面时，打开左侧“演示数据”。运行测试：

```bash
python -m unittest discover -s tests
```

## 数据源

使用 [AKShare](https://github.com/akfamily/akshare) 及公开行情接口，无需 API Key。全市场依次使用新浪、东方财富和腾讯，逐页检查供应商总数、页长度和唯一代码；供应商覆盖口径可能不同，不宣称已与交易所名册逐只核对。日线优先腾讯前复权，自动分钟使用有界腾讯接口，日线与分时成交量统一为股，并核验量额价格量级。次日OHLC分钟线使用新浪/东方财富，必须验证日期与连续性。量比缺失时沿用原有近5日同期估算公式。接口可能延迟、中断，Mac需开机联网且未休眠；保证超时后不给迟到名单，不保证每天能得到有效行情或Telegram准时送达。
